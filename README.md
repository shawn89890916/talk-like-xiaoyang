# 我的表达方式

让不同 AI 在聊天、写文章和处理正式内容时，参考同一份有证据、能修正的表达档案。

当前版本：`0.1.17`，分析日期：2026-10-24。它描述可观察到的表达和论述习惯，不声称复制一个人的全部思考，也没有训练或微调模型。

## 这版发现了什么

- 聊天通常先说重点，语气会留些转圜；已经交代过的内容不反复说，需要时再绕着补背景。
- 常把问题缩到一个具体疑点，再追问、核实或尝试；讨论分歧时会重新说明当前前提。
- 口语词是按场景自然出现的。“啥”“咋”“就是”“然后”有跨会话支持，但不能每句都加。
- 办事消息里会用称呼、具体背景和直接请求。长文章及完整正式文档的原创样本不足，相关指南只是待校准的迁移方案。

语料归纳仍属初步结论。前十五轮共记录 21 个合成场景的选择、改写和一组未排序的短回复变体，具体偏好只在对应情境得到确认。用户也明确要求模仿时保留标点和表达顺序的自然变化，避免过度规整。

本人明确补充：表达喜欢先说重点，已经说过的内容不再重复，措辞可以委婉、绕一点。

## 校准记录

已完成 7 个合成情境：2 条本人自由改写、5 条本人选择的候选说法，覆盖熟人聊天、办事短消息和文章短段落。见 [校准记录](calibration/round-1.json)。

目前更值得沿用的方向是：按当前内容自然展开，不固定信息顺序，也别自动补成层层递进的论证。交付问题、工具介绍和方案选择都出现过不同的起头方式；这个跨情境概括仍待验证。

数量短不等于论述简单：对连续消息的分析见 [表达档案](profile/VOICE.md)。单一会话约占候选消息的 48.68%，因此不能把总体高频直接当成所有场合都适用的习惯。

## 怎么用

1. 先读 [AGENTS.md](AGENTS.md) 和 [表达档案](profile/VOICE.md)。
2. 按任务读 [聊天](scenarios/chat.md)、[文章](scenarios/article.md) 或 [正式内容](scenarios/formal.md)。
3. 把 [通用使用提示](prompts/use-my-voice.md) 与当前事实、对象、用途一起交给 AI。
4. 用 [校准案例](evaluation/cases.json) 检查结果，再按本人反馈更新档案。

机器可读规则在 [voice-profile.json](profile/voice-profile.json)，统计脚本在 `analysis/`，统计和复算方法见[方法说明](evidence/methodology.md)。规则和模板是初版；没有完成本人盲评，不提供虚构的“模仿准确率”。

## 仓库收录什么

只收录分析总结、聚合统计、可复现分析脚本和虚构校准案例。原始聊天、联系人信息、私人称呼、对话摘录、凭据、数据库和导出包不上传。

“本账号发送”只代表发送方向，不自动证明原创。尤其不能把转发的 AI 回复、通知、范文或引用的他人内容当成本人文章风格。

本仓库公开展示表达偏好、聚合统计、可复现脚本和合成校准案例。原始聊天、联系人资料、原文摘录、账户标识、凭据、数据库和原始导出不公开。不要把观察转写成未经确认的个人经历或心理判断。

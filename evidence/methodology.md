# 分析方法与证据边界

日期：2026-10-24，时区：Asia/Shanghai。输入为本次在本机导出并校验通过的一对一微信记录；群聊没有进入输入。

## 输入与作者身份

完整导出包含 93 个会话、22,547 条消息。分析主输入是本账号发送的文本和引用回复正文，共 9,661 条，涉及 82 个会话。引用的他人内容没有混进“我的发言”正文。

这里能核实发送方向，不能核实每条文字的实际作者。内容中可见模板、转发或粘贴的迹象，因此不能把所有正式措辞、长文和论述当作本人原创。聊天内容中提到的经历、成绩、项目和第三方信息均未被转写为事实档案。

输入文件的 SHA-256 保留在 `corpus-stats.json`；原始文件只留本机，没有提交。摘要不是完整聊天备份，也没有覆盖其他聊天平台或全部历史。

## 两套统计

1. **全部本人文字**：9,661 条，描述本次实际发送的文本。
2. **候选风格样本**：用可审计规则标记链接、较长或多行格式化内容、代码或命令、分享模板、数字字段及疑似凭据等，保留 9,514 条。

147 条消息只从候选集剔除，没有从原始导出中删除。一条消息可以命中多个原因，因此原因计数之和可以大于 147。

## 标点、词条和可视化的复算步骤

下次更新这组统计时，原始导出保留在仓库外，并按以下顺序操作：

1. 记录导出范围、导出日期、时区和原始文件 SHA-256；确认输入仍是本账号发送文字与引用正文，群聊及他人内容不混入。
2. 使用 `analysis/analyze_markers.py` 的相同筛选规则生成候选集。先核对候选条数、会话数、字符数和源文件 SHA，再比较新旧范围；语料变化时不要直接横向比较比例。
3. 对预先列出的标点类别计算两个口径：至少含该类字符的消息数/候选消息总数，以及该类别所有字符出现次数/每千条候选消息。保留各具体字形的拆分计数；类别可重叠，一条消息可能同时含逗号和问号。
4. 结尾类型在去掉结尾引号、括号等闭合符后，按最后一个预设标点归类。没有预设标点或属于其他字符的情况归到 `none_or_other`，不人工猜测语气。
5. 对预先定义的词条作子串匹配。每项记录含词条消息数、消息占比、出现总数、每千条消息、每千字符和会话数；词条可能重叠、多义。完全匹配的短回复另行统计，避免把长句里的“好”当作独立回复。
6. 报告使用“候选词/表达”“出现频次”等描述；是否属于口头禅需结合上下文和本人确认。发送方向不能证明作者身份，任何频次都不推断心理或人格。
7. 从聚合 JSON 渲染 PNG 与 SVG。字号编码含该词的消息数，图上标点字形次数与类别消息占比要明确区分。检查汉字字体、数字、图例和尺寸；图中不含原句、联系人或消息级数据。
8. 每次重算都同步更新报告、图、README 摘要、本表达档案、版本记录和本方法说明。隐私检查及源数据校验通过后再提交。

从项目根目录运行示例（路径替换为本机导出位置）：

```powershell
python analysis/analyze_markers.py --self "D:\path\我的发言.jsonl" --output evidence/language-markers.json --markdown evidence/language-markers.md
python analysis/render_language_visuals.py --stats evidence/language-markers.json --png evidence/language-cloud.png --svg evidence/language-cloud.svg
python analysis/validate_repository.py --self "D:\path\我的发言.jsonl" --full "D:\path\个人聊天记录.jsonl"
```

统计脚本只写聚合数据，不生成逐条消息清单。完整校验也会确认输入 SHA、预期文件清单、联系人和账号标识、凭据模式及长原文没有进入发布文件。

## Obsidian 文稿的独立筛选

Obsidian 文本不加入微信导出文件、候选消息分母或任何聊天频率图表。每份文稿先按文档内的来源说明分类：本人提供并指定的当前稿件可以作为低置信度的文体样本，但若逐句编辑情况不清楚，就不称为纯原创；明确 AI 生成、助手建议、外部题目、返稿、转发引用、资料摘录不作为本人原写样本；有混合编辑但无法区分各段来源的稿件暂不纳入。口述转写另列为 spoken/dictation，识别错误和口语停顿不得转成打字风格结论。

先按文体和用途分析单篇稿件的结构特征，再决定它是否能补充对应场景的表达指南。独立样本少时只记录“单篇稿件呈现出……”，保留低置信度和编辑来源限制；聊天、文章、个人叙事文书、正式邮件分别维护，不跨语料合并词频，不用某一文书事实写入个人事实档案。远端仅保存来源类别和抽象观察，不存正文、原句、人物名或经历细节。

筛选不是 AI 检测器，也不是原创性鉴定。它会漏掉较短的转发、范文、粘贴回答，也可能排除本人真正写的长段落。候选集不得标成“已确认自发原创”。

字符数按 Python Unicode 字符串长度计算，包括字母、数字、标点、换行和表情代码。百分位采用排序后下标 `int((n-1)*p)`；终止标点统计只检查预设标点，不能解释成语言学标注。

## 连续发言

在同一会话内按时间和消息编号排序。连续由本人发送的候选文本，若相邻间隔不超过 120 秒且没有其他非系统消息插入，就近似组成一个发言段。媒体消息和不合格文字会打断分段。

得到 6,609 个候选发言段，其中 2,004 段包含多条消息，561 段至少有三条。4,909 条候选消息位于多消息发言段内，占 51.60%。多消息段占全部段数 30.32%，所以不能说“每次都连续发很多条”。

这套定义只衡量分条发送现象，不能精确复原一次思考或一次自然对话回合。

## 定性阅读

人工阅读覆盖最初抽样中的 310 条单条消息，以及最终筛选样本中的 45 个连续发言段。完善筛选后，最终抽样集合包含 376 个单元：321 条单条消息、45 个连续发言段、10 条来源不确定的对照项。最终筛选、统计与抽样可复算；没有把抽样集合说成已经逐条完成原创性核实。

选样覆盖不同月份、会话、长度和预设连接词，并包含若干长段落与对照项。原始或初步遮盖后的审阅材料始终留本机；本仓库只保留聚合统计和人工归纳，不保留逐条审阅文本。

语义结论来自抽样阅读，因此标为初步归纳。不要把它描述成全量语义逐条审核或本人认可。

## 偏差与反例

- 单一会话占候选消息约 48.68%，前五个会话约占 65.43%；高频可能受特定交流对象影响。
- 词频报告同时保留出现会话数；这些是子串计数，词语可能重叠或有多个含义，不能直接证明心理动机。
- 文字输入不覆盖图片、语音、贴纸的完整表达作用；媒体发送计数单独记录。
- 有的自然短句带修正、重复或省略，不应在所有文体里刻意模仿这些形式。
- 完整原创文章、正式邮件及报告没有建立单独的可信样本集，不能据此验证跨文体复刻能力。

## 哪些是本人明确要求

非必要避免“不是……而是……”及类似句式，来自当前用户提供的指令；这是明确要求，不是从词频猜测出来的偏好。本人另明确补充，表达先说重点、已说过的不重复，措辞可委婉且稍绕一些；作为单独的已确认规则记录。

本次用户明确希望在聊天、文章、正式内容中使用，并要求把整理结果保存在 GitHub。未经本人确认的语义归纳不会升级为已确认规则。
